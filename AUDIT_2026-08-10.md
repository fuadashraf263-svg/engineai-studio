# Audit — 10 Aug 2026

An adversarial pass over the verify-first core, plus the first standard-parts data.
Method: re-run everything and try to break it, rather than read it and agree with it.
Every claim below was reproduced on this machine.

The headline: **four real defects, two of them serious, all four in code that was
previously reported as passing.** Three of the four were invisible precisely because
the thing that was supposed to catch them was the thing that was broken.

---

## 1. The sandbox could read the entire Windows C: drive — FIXED

`sandbox_runner.py` is the isolation boundary for model-generated code. Its docstring
claimed "NO network and NO access to the host home directory". The flags were:

```
--ro-bind / /   --tmpfs /home --tmpfs /root --tmpfs /tmp   --unshare-all ...
```

`--ro-bind / /` mounts the whole filesystem read-only into the sandbox, and only
`/home`, `/root` and `/tmp` were masked. **Every other mount stayed readable** — and on
WSL that includes `/mnt/c`, i.e. the entire Windows drive. Reproduced directly:

```
mnt_c_visible_to_sandbox: True
top_level_entries: ['$Recycle.Bin', ..., 'Program Files', 'Users', 'Windows']
```

Network isolation did not mitigate this, because generated code does not need the
network to exfiltrate: **its stdout is captured and returned to the caller by design.**
Read access plus a return channel is a full confidentiality bypass.

Fixed by masking `/mnt`, and while in there, capping address space so a runaway
allocation cannot exhaust host RAM. Both are now asserted in the selftest, so the
claim is tested rather than asserted in a docstring.

*Rejected fix, recorded so it is not retried:* `RLIMIT_NPROC` for fork bombs. That
limit is **per real UID, system-wide**, so it counts every process the user already
has and intermittently broke bwrap's own namespace setup
(`Creating new namespace failed: Resource temporarily unavailable`). Fork bombs are
already contained by the `--unshare-all` PID namespace — the tree dies with the parent.
Memory is the one runaway resource a PID namespace does *not* contain, so only that
is rlimited.

## 2. The drawing engine was silently producing blank sheets — FIXED

`drawings_project.py` was committed as "14/14 PASS, a real general drafting engine".
On re-run it returned `0.0 x 0.0` for **every view of every part**.

Cause: OCP renamed `TopoDS.Edge_s` to `TopoDS.Edge`. Every edge extraction raised
`AttributeError` — and was swallowed by a bare `except Exception: pts = []`. The engine
produced empty geometry and reported success. `design_part.py` depends on projection,
so it was silently degraded too.

This is the most instructive failure of the four. The bug was not the API rename; the
rename is normal. **The bug was that a dependency break could not surface.** Fixed the
call, and made extraction failures print to stderr so the next drift is loud. The
handler still degrades rather than crashing — one malformed edge should not kill a
sheet — but it can no longer do so in silence.

After the fix, real geometry: plate 120×80, 28 hidden edges, the L-bracket's internal
step visible.

## 3. The consensus gate confused "same number" with "same answer" — FIXED

Two independent defects in the gate that decides whether an answer is trustworthy.

**Numeric agreement ignored units.** Clustering compared bare floats, so
`12.566 m²` and `12.566 ft²` counted as agreement. Now clustering happens in base SI,
and runs of different dimensionality can never join a cluster however close the numbers.

**The unit check verified dimensionality, then returned the raw number anyway.** If the
majority of solvers agreed in ft² and the caller asked for m², `has_dimension` passed
(both are areas) and the receipt reported `answer: 12.566`. A caller reading `answer`
is wrong by 10.76×. The agreed value is now converted into the requested unit
(1.16742 m² in that example).

Regression tests cover both directions, including the converse that must keep working:
0.001 m, 1.0 mm and 0.1 cm *are* the same answer and must still count as agreement.

## 4. `design_part` certified parts that were strong but unusable — FIXED

The end-to-end workflow sized on bending stress alone. Deflection was computed,
reported, and **never constrained**. Since deflection grows with span³ while bending
moment grows with span, deflection governs on any long member — exactly where a naive
sizer is most confident.

Demonstrated: a 40×50 section on a 1500 mm cantilever clears FoS 2.06 and sags 27 mm,
against a 6 mm serviceability limit. The old code stamped that `verified: true`.

Sizing now satisfies strength **and** a deflection limit (default span/250, the
Eurocode-order general limit for members carrying no brittle finish; caller-overridable).
The check appears in the receipt, and the report states which criterion governed. On
the default 300 mm case the answer moved 23 mm → 29 mm, and the report now says
`governed_by: deflection` where that is true.

## Known and accepted, not fixed

Recorded honestly rather than quietly left out.

**The receipt is tamper-*evident*, not tamper-proof.** `content_hash` is a plain
SHA-256 over the body with no secret. A forged receipt with a recomputed hash passes
`verify_receipt()` — reproduced. This is fine for its real job (detecting accidental
corruption, and giving answers a reproducible content-address) but the word
"tamper-evident" oversells it against a motivated forger. If receipts are ever shown to
a third party as provenance, this needs an HMAC or a signature — `owner.py` already has
signed tokens to build on.

**`solve_or_build.match_tool` routes on substring.** `"why did the rc_filter blow up in
1998"` routes to `rc_filter`, and `"do NOT use pipe_flow"` routes to `pipe_flow`.
Negation and context are invisible to it. Low severity today because the tool set is
small and the agent normally routes via the model, but it will not scale.

**Consensus across samples from one model does not decorrelate errors.** If a model is
confidently wrong the same way three times, the gate "verifies" a wrong answer.
`model_router.py` exists to fix this with diverse models, and the routing logic is
correct and tested — but on this hardware, holding three models resident is what caused
the OOM in the first place. The honest statement is that consensus catches *unstable*
errors, not *systematic* ones.

**`structural.py` checks bending only.** No shear, no lateral-torsional buckling, no
web crippling, no fatigue. Fine for the rectangular sections it was written for; a real
risk now that catalogue I-sections are available, because slender I-beams are exactly
what lateral-torsional buckling governs. **This is the highest-value next fix.**

## Added: `standards.py` — standard sections and fasteners

The vocabulary a real user needs to state a requirement the way their supplier speaks
it: *IPE 200*, *M12 class 8.8* — not "a 40×23 bar".

The design rule is that **wherever the standard defines a quantity by a formula, the
formula is implemented and the published table is only the test oracle.** Data that can
be derived is derived; data that must be tabulated is cross-checked.

- **ISO metric threads.** Tensile stress area computed from pitch via the ISO 724 basic
  profile, matched against all 12 published ISO 898-1 values — worst error 0.21%. M12
  derives to 84.27 mm² against the textbook 84.3.
- **ISO 898-1 property classes are self-describing.** For class X.Y, tensile strength is
  X×100 MPa and yield is Y/10 of that. Asserted for all five classes rather than typed in.
- **18 EN 10365 IPE sections**, each cross-checked three independent ways: elastic moduli
  must equal I/(h/2) and I/(b/2), mass must equal A × 7850 kg/m³, and area must equal the
  exact fillet-inclusive geometry. Published Iy is additionally bounded above the
  no-fillet lower bound — which catches a transposed digit that the ratio checks alone
  would not.

24/24 selftest. Three agent tools: `standard_section`, `select_section` (lightest
section meeting a required Z, with an honest "nothing in range" when the catalogue runs
out) and `bolt_sizing` (capacity plus a conservative bolt count).

**What this does and does not prove.** It catches transcription error — the failure mode
that actually bites when a human copies a catalogue. It does not make the numbers
certified, and it is one section family out of many. Use the manufacturer's current
datasheet for anything that gets built.

## Session 2 — depth added, and where the ceiling actually is

The brief was "download all engineering data available… all geometry, all disciplines,"
so the first honest thing to record is **what is not obtainable and why**, because it
shapes everything else:

- **MMPDS, ASME Y14.5, the full ISO/EN standard texts, AISC's complete shapes database,
  SKF/NSK bearing catalogues** are paywalled and license-restricted. They cannot be
  redistributed inside a product. `MASTER_PLAN.md` already keeps `books/shippable`
  and `books/reference` separate for exactly this reason, and that separation is the
  foundation of the business, not an inconvenience to route around.
- **"All disciplines" is not a data problem.** The blocker is not that pipe tables are
  hard to find; it is that every number needs a verification path before it can be
  trusted, and writing that path is the slow part. Padding the database with unchecked
  values would reproduce the "87 citations written from memory" failure this very
  document was created to record.

So the work went to depth over breadth, on the item ranked #1 above.

### Shear and lateral-torsional buckling — the dangerous gap, closed

`structural.py` checked bending stress only. For a real steel section that omission is
**not conservative**: a 12 m unrestrained IPE 300 buckles laterally at 35.3 kNm against
an in-plane capacity of 172.8 kNm. Bending-only design overstates that beam by a factor
of five and calls it adequate.

`steel_design.py` implements EN 1993-1-1 classification (Table 5.2), shear (6.2.6) with
the moment-shear interaction (6.2.8), and LTB (6.3.2). Nothing is trusted to memory:

- `chi_LT(0.2)` must equal **exactly 1.0** for all four buckling curves, because
  phi = 0.52 and sqrt(0.52² − 0.2²) = 0.48. That one identity pins the plateau constant
  and the leading 0.5 without consulting any table.
- `Mcr` is verified by killing each term: with `It=0` it must collapse to the pure
  warping form, with `Iw=0` to the pure St Venant form. Both hold to 1e-12.
- Shear yield `fy/sqrt(3)` is the von Mises result; the interaction is checked for
  continuity at V/Vpl = 0.5 and completeness at 1.0.

`structural.py` now carries a scope warning pointing here.

### Hollow sections — because "your beam fails" needs an answer

Adding LTB made a new question askable, so it needed answering. A closed section
carries torsion as shear flow rather than by warping: **SHS 200×200×10 has 356× the
torsion constant of an IPE 300**, and at 12 m its chi_LT is 0.983 against 0.204 — a
1.7% penalty instead of 80%.

CHS needs no catalogue: every tube property is closed form, so it is computed and
cannot be mis-transcribed, and `J = 2I` exactly (perpendicular axis theorem) is asserted.
SHS is tabulated and gets the IPE treatment — plus Bredt's `t(b−t)³` reproducing the
published torsion constant within 5%, which independently validates that whole column.

The selftest deliberately records the **unflattering** half of the result: the 12 m span
that failed as an IPE 300 at 3.06 utilisation passes bending as an SHS at 0.75 — and
then fails on deflection at 173 mm against a 48 mm limit. Solving one limit state
exposes the next. A tool reporting only "LTB fixed" would be quietly misleading.

### Materials 4 → 10, and a correction to what the check proves

The source for the new entries tabulates E and nu but **not G** — so G had to be derived,
which makes the module's headline check `G == E/(2(1+nu))` a *tautology* on those rows.
Previously every material was checked identically and the summary implied uniform
evidence. Each entry now records whether G was independently sourced, and the selftest
counts the two separately:

> 10 materials: 4 with an independently sourced G (real cross-check),
> 6 with G derived from E and nu (tautology).

Real verification was found elsewhere: ASTM A536 ductile iron grades are self-describing
("60-40-18" = 60 ksi tensile, 40 ksi yield, 18% elongation), so the selftest decodes the
grade *name* and checks the stored strengths against it. Grey iron is flagged brittle,
and `design_part` now **refuses** it rather than substituting tensile strength into a
yield-based factor of safety — a substitution that would quietly overstate the margin on
a cast iron part.

### Honest status against "beat Manus"

Where this now genuinely leads a general agent: it will tell you a beam fails on lateral-
torsional buckling, and no general-purpose model reliably does that unprompted. Where it
does not: one section family per shape, one code (Eurocode, no AISC/National Annex), no
connections, no fatigue, no second-order analysis, and the drawing engine produces correct
projected geometry but still lacks full dimensioning and GD&T on the sheet. It is deeper
than a general agent in a narrow strip, and far narrower than a practising engineer.

## Session 3 — the data was already here, and unreachable

Brief: research every discipline and download all available engineering data.

**The main finding is that most of it was already on this machine and could not be
imported.** The project's own `fluids.py` shadowed the third-party `fluids` package,
so inside `~/engineai` every `import fluids` resolved to the project module. That one
filename silently cost:

| Blocked | What it carries |
|---|---|
| `chemicals` | ~20,000 compounds — MW, Tb, Tc, Pc, vapour pressure, Cp |
| `ht` | convection, boiling, condensation, radiation, exchanger sizing |
| `thermo` | flash calculations, VLE/LLE, cubic equations of state |
| `generators_pro.pipe_system` | `ImportError` on `Reynolds`/`K_from_f`/`bend_rounded` |
| `generators_pro.moody_chart` | `TypeError` — wrong `friction_factor` signature |

`LACKINGS.md` had recorded these as *"installed, unwired"*. They were installed and
**unimportable**, which is a different and worse problem: no amount of wiring would
have fixed it. Nothing noticed because nothing exercised those paths.

Renamed to `engineai_fluids.py`. All five work now. The two generator failures were at
least loud (`ImportError`, `TypeError`) rather than silently wrong — checked, because
`moody_chart` did import a real `friction_factor`, just the wrong one.

Also installed: `ht`, `thermo`, `chemicals`, `psychrolib`, `iapws`, `ambiance`,
`periodictable`, `mendeleev`, `lcapy`, `PyNiteFEA`.

### `capabilities.py` — the list, built so it cannot lie

The obvious way to answer "what data do we have" is to list installed packages. That
is exactly what would have reported `chemicals` as present throughout the period it
was unimportable. So every entry carries a **probe**: a small calculation with a
known-correct answer, executed at call time. A capability is available only if it
returns the right value.

Probes are chosen so a broken, shadowed or substituted library cannot accidentally
satisfy them — water density 998.2 kg/m³ at 20 °C, inch→mm exactly 25.4, errors of 3
and 4 combining in quadrature to exactly 5, LMTD against its closed form, standard
gravity exact by definition.

**27/27 verified across eight disciplines:** fluids 5, methods 6, geometry 4,
structural 3, electrical 3, chemical 2, thermal 2, materials 2.

The selftest distinguishes two cases that matter: an installed-but-**wrong** library
is a defect and fails the suite; a **missing** optional library is a known gap and is
merely noted. It also fails if the verified count collapses below 20, which would
catch a repeat of the collision above.

Three agent tools: `list_capabilities` (probed, so it cannot overclaim), plus
`fluid_property` (CoolProp real-fluid EOS) and `chemical_property` (name or CAS).

### Discipline coverage, stated honestly

Solvers now span eight disciplines. **Standard-parts data is still structural only** —
there are no pipe schedules, cable tables, or pump curves, and that gap is unchanged.
The distinction matters: EngineAI can compute the pressure drop in a pipe with real
fluid properties, but cannot yet tell you which *standard* pipe to specify.

## Session 4 — competitive analysis, and what NOT to copy

Brief: research Manus and add its capabilities, better.

The feature list (slide decks, website and mobile app builders, marketing/sales/finance
workflows) is **deliberately not copied**. Those compete on breadth, which is the one
axis where a general agent with a large team will always win, and adopting them would
dilute the only thing EngineAI is better at. Manus's own published blueprint makes the
argument for us — it concludes that the improvements that matter are *"better source
provenance… lower hallucination rates through retrieval and verification"* and
*"explicit authorization"*. That is EngineAI's existing thesis, written by a competitor.

So the research question became: **what do independent reviewers record as actually
going wrong?** Three failures recur, and all three are architectural, not model quality:

| Documented failure | Evidence |
|---|---|
| **Hallucinated success** | A two-week production trial catalogued 14 failure categories, "hallucinated success reports" among them |
| **Unpredictable cost** | The vendor's *own* help docs say model-produced credit estimates are *"hallucinations rather than factual commitments"* |
| **No durability** | Complex tasks fail mid-stream; error compounds across multi-step runs |

`grep` over `agent_loop.py` for risk / approval / cost / durable returned **zero
matches**. All three were open. `task_ledger.py` closes them by structure:

**Completion gate.** Every tool observation is scanned for claimed file paths, and a
task cannot report success unless those files exist and are non-empty. Completion is a
checked fact, not a model assertion. Proven inside the agent loop: a run claiming
`/tmp/definitely_not_written.dxf` returns `failed_verification` with *"DELIVERABLE
MISSING"*, while a real artifact passes the identical gate. Receipts are re-verified,
so a tampered one also blocks completion.

**Cost preflight.** Because nearly the whole pipeline is deterministic local
computation, cost is **counted, not estimated** — a structural advantage a
browser-and-LLM agent cannot match. `beam_design` → 0 model calls for tools, hard
ceiling of 8 for planning. `derive from scratch` → correctly 8, flagged non-local. It
refuses to emit a dollar figure (a test asserts no `$` appears), because that depends
on the routed provider and inventing one would be the very failure being fixed.

**Durable ledger** (append-only JSONL, fsync'd, reloadable after process death) and
**risk classification** of all 24 tools. An unclassified tool defaults to
`irreversible` and demands approval — the default fails safe, and a test pins it.

### The honest competitive position

EngineAI wins on: verified numbers with receipts, deliverables that are checked to
exist, countable cost, and engineering depth a general agent has no reason to build.
It loses on: breadth, polish, hosted infrastructure, browser automation, and
everything in the Solutions menu. That trade is the strategy, not an accident.

## Still open, in the order I would do it

*(Items 1–3 were done in session 2; what follows is the remaining list.)*

1. **A second steel code — AISC 360.** Everything today is Eurocode. A US user cannot
   use this, and adding AISC would also cross-validate the Eurocode results: two
   independent codes agreeing on a capacity is far stronger evidence than one.
2. **HEA/HEB, RHS, angles and channels**, plus more SHS/CHS sizes. `standards.py` is
   shaped for it — each family is data plus the same cross-check pattern.
3. **Column buckling and combined axial + bending** (EN 1993-1-1 6.3.1 and 6.3.3).
   Right now every member is assumed to be a beam. A strut is silently unsupported,
   which is the same class of gap LTB was.
4. **Standard parts for the other disciplines.** `fluids.py` and `circuits.py` have
   verified solvers but no catalogue layer — no ASME B36.10 pipe schedules, no cable
   tables, no pump or fan curves. This is the honest boundary of "all disciplines":
   the *solvers* span several, the *standard data* is currently structural only.
5. **Dimensioning and GD&T on the projected drawing sheet.** The projection engine
   produces correct geometry; the sheet still lacks hole-location dimensions,
   diameter callouts with leaders, and the existing `gdt.py` composed onto it. A
   machinist could not yet build from the output alone.
6. **HMAC the receipt** if provenance is ever shown to a third party.
7. **Connections, fatigue, second-order effects.** Large, and each is a genuine
   speciality. Worth stating plainly that they are absent rather than implying the
   member checks constitute a complete design.
